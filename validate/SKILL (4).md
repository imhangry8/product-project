# 数据效果验证
为【用户输入的产品/功能】建立"上线前定义指标 → 上线中实验验证 → 上线后监控排查 → 结论反哺迭代"的完整数据验证闭环。产出可直接嵌入PRD的埋点需求与验证方案。

## 目标
1. 上线前：定义一套可衡量的指标体系，并输出研发可执行的埋点需求
2. 上线中：用A/B实验科学验证功能效果，给出 ship / extend / stop / investigate 决策
3. 上线后：通过漏斗分析和异常排查定位问题，把数据结论转化为下一轮迭代输入

## 输入
- 用户提供的PRD、功能说明或项目目标（优先读取，提取成功标准）
- 用户提供的实验数据、行为数据CSV/Excel、埋点导出
- 无真实数据时：使用Python生成模拟数据，或基于公开数据集（如阿里天池用户行为数据集）演示完整流程，并明确标注「演示数据」

## 模块一：指标体系设计（上线前）

### 指标分层框架
- **北极星指标（1个）**：最能代表产品核心价值交付的指标，必须是先行指标
- **输入指标（3~5个）**：驱动北极星的可操作杠杆（如：新用户激活率、功能渗透率）
- **健康指标**：产品整体健康护栏（留存、崩溃率、加载时长、客诉量）
- **业务指标**：收入、成本、单位经济模型（GMV、ARPU、CAC/LTV）

### 好指标的4条标准（Lean Analytics，逐项校验）
1. **可理解**：团队能用共同语言讨论
2. **可对比**：看时间趋势，不看单点快照
3. **比率优先**：比率/速率比绝对值更有信息量
4. **可行动**："如果这个指标不变，你的行为会改变吗？"——不会，就是坏指标

### 三类必要判断
- **虚荣指标 vs 可操作指标**：下载量、总注册数是虚荣指标；留存率、转化率才是可操作指标
- **先行 vs 滞后**：先行指标（如客诉量、功能使用频次）能更早预警，滞后指标（如季度留存）用于最终复盘
- **定量 vs 定性**：数据告诉你WHAT，用户反馈告诉你WHY，两者必须结合

### 输出：指标定义表
| 指标 | 口径定义（分子/分母、时间窗） | 数据源 | 可视化 | 目标值 | 告警阈值 |
|---|---|---|---|---|---|

### 输出：埋点需求清单（供PRD「数据需求」章节引用）
| 事件名 | 触发时机 | 事件属性 | 用途（对应哪个指标） |
|---|---|---|---|
> 原则：埋点必须能回答指标体系里的每个指标，否则不埋

## 模块二：A/B实验验证（上线中）

### 实验设计
1. **假设**：可证伪的单变量假设（"将注册按钮从A改B，可提升注册转化率"）
2. **变量唯一**：一次实验只改一个因素
3. **样本量**：n = (Z²α/2 × 2 × p × (1-p)) / MDE²，检验效能≥80%，否则标记「检验力不足」
4. **周期**：至少跑满1~2个完整业务周期，排除新奇效应
5. **分流**：检查样本比例是否匹配（SRM检验）
6. **护栏指标**：提前定义不能恶化的指标（收入、加载时长、整体留存）

### 结果分析（提供原始数据时用Python脚本计算）
- 对照组/实验组转化率、相对提升 = (variant - control) / control × 100%
- p值（双尾z检验或卡方检验）、95%置信区间
- **统计显著 ≠ 业务显著**：p<0.05但提升<0.1%可能不值得上线成本

### 决策输出
| 结果 | 决策 |
|---|---|
| 显著正向，护栏无恶化 | **Ship**：全量上线 |
| 显著正向，护栏恶化 | **Investigate**：先弄清权衡再上线 |
| 不显著，正向趋势 | **Extend**：延长周期或扩大样本 |
| 不显著，持平 | **Stop**：无差异，停止实验 |
| 显著负向 | **Revert**：回滚，分析原因沉淀认知 |

## 模块三：漏斗分析与异常排查（上线后）

### 漏斗分析
- 定义核心漏斗（如：曝光→点击→注册→激活→留存）
- 输出各环节转化率，定位最大流失环节
- 对流失环节做维度下钻：渠道/版本/人群/时间切片

### 异常排查框架（指标下跌怎么办）
1. **先验证数据**：埋点是否异常、统计口径是否变更——排除"假下跌"
2. **维度下钻**：按渠道、版本、地区、新老用户拆分，定位异常子集
3. **时间对齐**：下跌时间点与发版、运营活动、外部事件（节假日、竞品动作）对齐
4. **定量+定性**：数据定位环节后，用用户反馈/访谈解释WHY
5. **输出**：结论 + 影响面 + 修复建议，输入需求池

### 复盘节奏建议
- 每日：健康指标（崩溃、客诉）
- 每周：输入指标与漏斗趋势
- 每月：北极星指标与OKR进度

## AI产品适配（可选模块）
当验证对象是AI功能时，补充效果评估维度：
- **模型层**：准确率、召回率、幻觉率
- **任务层**：任务完成率、一次通过率、人工接管率
- **标准定义与评估闭环**：评估集构建、标注策略、线上badcase回流机制

## 输出结构（完整验证方案）
1. 验证方案摘要（2~3句）
2. 指标体系定义表
3. 埋点需求清单
4. 实验设计 / 实验分析报告（按任务选一）
5. 漏斗与排查分析
6. 结论与迭代建议（每条标注「事实」或「假设」，假设给出验证方式）

## 最佳实践
1. 先定义指标再开发功能，避免上线后"无数据可验"
2. 指标宁少勿多，每个指标都要能触发行动
3. 不显著的结果也是结果，停止实验同样产生认知价值
4. 数据结论必须回流：明确写出"这个数据改变了哪个产品决策"
5. 连续监控同一指标的长期趋势，警惕单次波动过度反应

## 约束规则
1. 无真实数据时可用模拟数据演示，但必须标注「演示数据」，禁止编造真实业务数据
2. 统计结论必须附带置信度说明，不夸大不显著结果
3. 区分事实与假设，假设项标注【待验证】及验证方式
4. 不输出无法落地的建议，每条迭代建议要对应到具体数据证据
